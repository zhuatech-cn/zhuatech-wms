## 设计目标

第一版采用前后端分离的模块化单体，优先保证仓储流程清楚、部署简单和个人学习环境可运行。PC 管理端与 H5/PDA 作业端共享 Vue 工程，通过不同路由壳层复用登录、状态管理和 API 客户端；Java 根包为 `cn.zhuatech.wms`，MySQL 表统一使用 `wms_` 前缀。

## 运行结构

```text
Nginx / Vue SPA
├── /admin/*  主管与管理人员
└── /work/*   现场作业人员
      │ /api
Spring Security → Controller → Service → JPA Repository
                                      │
                               MySQL / Flyway
```

## 领域模型

- `InboundReceipt`：预约到仓、月台、供应商、收货和质检进度。
- `OutboundWave`：订单聚合、SKU 数、件数、拣选进度、承运商与截单时间。
- `InventoryBalance`：SKU + 库位 + 批次维度的可用、已分配和待上架库存。
- `WarehouseTask`：连接单据和现场人员的执行单元，覆盖六类作业。
- `WarehouseZone`：库区用途、环境、库位数、占用率与运行状态。
- `UserAccount`：账号、角色和默认仓库。

## 关键约束

1. 任务号、入库单号和波次号唯一。
2. 同一 SKU、库位、批次对应一条库存余额记录。
3. 完成数量被限制在 `0..plannedQty` 范围内。
4. 任务状态使用领域枚举，现场更新经服务层处理。
5. 数据结构变更只追加 Flyway 迁移，已发布迁移不可修改。

## 生产化演进

真正的企业仓库通常还需要多货主/多仓隔离、库存事务流水、预占与释放、波次和路径算法、事件总线、幂等、防重扫码、打印与设备服务、ERP/OMS/TMS 接口、审计日志、可观测性、灾备以及自动化设备调度。当前版本为学习和交流骨架；生产部署必须取得商业授权并完成针对性设计、安全加固与压力验证。
